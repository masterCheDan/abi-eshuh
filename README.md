# Abi-Eshuh — 蔚蓝档案学生技能排轴验证器

Abi-Eshuh 是基于 React、TypeScript 与 Vite 的纯前端工具。它记录用户指定的技能事件和触发事实，并以确定性引擎验证学生技能的目标、前置状态、Cost、牌序、效果生命周期和可审查结果。

它的目标是让同一份方案在相同数据与规则版本下得到相同的推演结果；它不是 Boss 战斗模拟器，也不会猜测概率、随机目标、血量或攻击／换弹等外部战况。

## 当前能力与边界

| 范围 | 当前行为 |
| --- | --- |
| 学生技能事件 | EX、公共技能、装备公共技能、被动／额外技能与变身后 EX 可作为结构化事件录入；引擎先验证再原子执行。 |
| 目标与触发事实 | 用户可选择一个或多个目标。概率、随机目标、血量阈值、攻击／换弹及其他外部条件必须由用户确认。 |
| 效果状态 | Buff、Debuff、护盾、控制、减费、召唤、叠层、变身和驱散具备状态及审计路径；每个数据项的支持等级由规则登记检查公开。 |
| Cost 与牌序 | 使用同一份引擎结果展示费用、减费、欠费、Cost 上限与牌序；失败施放不会扣费、消费次数或改变牌序。 |
| 自动 NS | 默认关闭，且只有明确逐技能审查的自身周期效果可开启。目前为堇 P/G 与明日奈（兔女郎）P。延迟后立即释放，下一周期从实际释放帧重新计算。 |
| 未审查 NS | 仅作为待确认建议；攻击次数型 NS 没有可信普攻完成记录前不会自动施放。 |
| Boss | Boss 只作为敌方目标及环境时长／护甲占位；不结算 Boss 血量、攻击、阶段、CC 槽或机制。 |
| 普攻 | 不生成可信的普攻、扣弹或换弹动作；动画近似值只可用于待确认建议，不能作为自动触发证据。 |

“规则登记检查通过”只表示数据项有明确处理策略与限制说明，并不表示全部技能机制已完整实现。`implemented`、`manual_fact`、`state_only` 与 `partial` 的区别会保留在检查结果中。

## 使用方式

1. 在编队面板选择学生，并设置技能等级、星级、专武和爱用品。
2. 在技能面板或时间轴录入技能事件，选择目标并确认需要的外部触发事实。
3. 在“自动 NS”面板查看资格。先打开总开关，再为已审查学生选择“自动”；已有 NS 事件必须由你保留或删除，程序不会转换它。
4. 阅读时间轴的动作、Cost、效果和审计记录。实线代表引擎接受的动作，虚线表示自动 NS 的等待区间。
5. 导出 v5 分享码。它会保存队伍养成、环境、时长、牌序、事件事实和自动 NS 设置；有待确认建议时不能导出。

旧 v0.0.1—v4 分享码可以导入。缺少自动 NS 设置的旧方案会明确迁移为关闭的手动模式，而不是自动改变结果。

## 界面功能

- 学生搜索与筛选、阵容位置配置、星级／专武／爱用品选择。
- 多目标技能事件编辑、手动触发事实及条件结束帧。
- 费用曲线、牌序状态、动作记录、效果审计、召唤物目标和紧凑常驻 Buff 标记。
- 中文、英语和日语界面主题；浅色、深色与跟随系统主题。

## 架构

```text
src/
 ├── domain/rules/       # 版本化规则目录、触发和覆盖登记
 ├── engine/             # 纯 TypeScript 推演、状态与审计结果
 ├── stores/             # Zustand 方案、编队、时间轴和调度设置
 ├── components/         # React 时间轴、编队、技能与环境界面
 ├── data/               # 学生与 Boss 静态数据
 └── utils/              # 分享码、导入准备和文本导出
```

## 本地开发

需要 Node.js 24 系列与 pnpm 10。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

| 命令 | 作用 |
| --- | --- |
| `pnpm test` | 运行回归测试。 |
| `pnpm lint` | 运行 ESLint。 |
| `pnpm check:effects` | 验证规则登记、处理器绑定和学生数据覆盖。 |
| `pnpm build` | 类型检查并生成生产构建。 |
| `pnpm data:build` | 从原始数据生成运行时学生数据库。 |

GitHub Pages 构建依次执行测试、Lint、规则登记检查和生产构建，使用与本地一致的 Node 24 系列。

# 第四步 4.2：技能动作记录与中断边界

本轮把已接受的 EX/NS/SS/控制施放纳入统一动作生命周期；不把普攻动画近似值升级为自动攻击事实。

## 已完成

- 新增 `ActionSystem`，统一记录动作开始、效果实际生效、完成、控制更新和中断。
- 每次成功施放拥有引擎内部唯一 `actionId`，即使用户事件 ID 相同，也不会把两个施放的延迟效果混为一谈。
- 动作日志带有计划结束帧、实际结束帧、状态（执行中/完成/中断）和中断帧；同一帧结束视为完成，早一帧才是中断。
- 延迟效果和召唤物绑定施放实例。动作中断时，已经生效的效果保持独立；尚未生效的效果不会被擅自取消，并记录 `UNVERIFIED_PENDING_INTERRUPT` 诊断。
- 控制状态通过同一动作系统同步：控制会截断当前技能、延长控制动作到真实结束帧；控制解除后立即恢复空闲。非法/费用不足施放仍在创建动作前拒绝。
- `SimulationResult` 新增 `actionEvents` 与 `schedulingDiagnostics`。时间轴动作轨道改为只读这些结果，不再使用旧的独立普攻片段推算；计算中隐藏上一轮结果。
- 普攻近似模块保留给攻击次数 NS 待确认建议使用，并在注释中明确不属于引擎攻击完成证据。

## 有意保留的边界

本轮尚未实现可信普攻循环（准备、逐发扣弹、换弹、完成计数、攻速和中断恢复），因此没有生成 `AA`/`RELOAD` 伪动作，也没有开启自动 NS。代表学生的这些时点仍由 4.1 动作预检逐项标记。没有结构化规则的延迟效果按现有状态行为继续推演，但会在动作诊断中显式提示，不能据此认证自动资格。

## 验证结果

- 新增动作生命周期集成测试：延迟效果链接、中断截断、控制更新和解除、失败施放原子性、零时长边界、模拟重复一致性、轨道只读投影和模拟结束截断。
- 全量测试：231 项通过；类型检查、Lint、规则登记检查、生产构建均通过。
- 规则登记结果：错误 0；动作预检覆盖 272 名学生，自动资格仍为 0。
- 生产构建保留 500 kB 以上 chunk 提示，本轮不做打包优化。

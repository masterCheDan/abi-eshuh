## 结果

B02—B04 的四项预期失败全部改为正常回归，并保留 B01。全套测试现在为 30 个文件、252 项通过，没有预期失败或跳过项。本步不代表全部学生特殊机制已完整实现。

### 触发事实

- `src/domain/triggerEvidence.ts` 统一规范化两个来源字段。缺失字段补齐；两者均缺失迁移为 manual；来源非法、显式 null 或矛盾均拒绝。
- 分享解码、时间轴恢复、桥接层和直接引擎输入共用此规范化逻辑。桥接和恢复不会用默认值覆盖冲突事实，而是保留给引擎报错。
- 外部自动事件只接受当前爱用品配置对应、已登记、无需手动目标或外部事实的周期 NS，帧数必须为开战起算的正整数周期倍数；重复事件保留输入顺序中的首个。
- 自动 EX、未登记自动技能、攻击次数型自动事件及外部伪造开局/关联 EX 事件被拒绝。开局 PS/WP 也不能通过改成 manual 绕过校验。
- 来源、帧数和触发资格在牌序推断及事件状态变化前校验，使用 `INVALID_TRIGGER`。概率效果、已登记 Size 外部条件及攻击次数 NS 分别要求相应人工原因；普通 EX 不强制额外原因。
- 补上 `controlledUntil` 的直接施放检查：受控事件拒绝且不顺延。测试比较拒绝前后的完整结果，排除扣费、牌序、活动效果和审计污染。

### 待确认建议

- `scheduleNsBlocks` 返回独立的 automatic 事件与 `NsSuggestion`，建议不放入引擎输入。
- 攻击次数推算仅提供建议帧；目标选择或外部条件未确定的周期技能同样只能生成建议。
- 时间轴使用虚线“待确认 NS”按钮，可修改帧、选择目标和确认原因。确认后才生成普通 manual NS，并记录 `action_event` 等事实。
- 重复预排替换未确认建议；不删除人工事件，不重复加入已有周期事件或已确认的建议。
- 旧攻击次数型自动 NS 保留原来源并明确报错。点击原技能块可显式转为人工确认，不能静默代替用户确认。
- 待确认建议持久化到本地快照；仍有建议时分享码导出报错，复制和下载禁用。
- 技能卡区分可自动周期触发和需人工确认，不再统一标为自动触发。

### 分享与批量导入

- 新 v4 输出按槽位对齐的 `levels` 和实际 `maxFrame`，保留等级、星级、专武、爱用品、牌序、环境、多目标、技能引用、召唤逻辑引用及触发事实。
- EX 等级范围 1—5，NS/SS 范围 1—10；空槽 levels 为 null。非法的已存在字段拒绝，不补默认值。maxFrame 为非负整数，明确的 0 保留。
- 旧码缺失等级时使用 5/10/10 并提示；缺失时长时按已选 Boss/难度推导，无数据时为 5400 帧。继续导入 v0.0.1—v4。
- 同帧同槽位事件保留原有顺序，不再用 eventId 排序。新 v4 同时写入一致的来源字段。
- 旧的不可解析召唤 ID 保留为原始事实，让引擎报错，不在再次导出时悄悄丢弃目标。
- `preparePlanImport` 先完整校验结构，未知学生、空施放槽位、非法目标槽位及无法解析的技能引用导致整体失败；战斗层面的无效事实可导入后编辑。
- `importPlanIntoStores` 在结构成功后用事务统一应用编队、环境和时间轴；事务合并重算请求，失败不修改 Store。
- `currentPlanSnapshot` 与 `exportPlanSnapshot` 供 UI 和测试共用。导出使用真实 Boss、难度、护甲、地形与时长，不再使用弹窗内固定环境。
- 第一阶段分享回归调用实际准备函数和桥接层，不再手写另一套导入逻辑。覆盖非默认等级和完整 SimulationResult 一致性，包括原 NS 数值从 10 变成 100 的回归。

## 规则登记与仍保留的边界

已更新共享目录中 manual、周期 NS 与攻击次数 NS 的策略和限制说明。支持等级统计仍是使用位置数，并非完整技能数量：implemented 2251、manual_fact 907、state_only 1285、partial 2516。

- 概率不掷骰，血量不推导。用户确认是事实声明，不是引擎已经验证真实攻击、换弹、随机选择或血量的证明。
- 当前明确要求的人工事实来自结构化 Chance、Size 条件和已登记的攻击次数 NS。尚未结构化的特殊外部条件依旧属于登记中的限制，不通过描述文本补猜规则。
- 周期事件受控或冲突时拒绝，不自动延迟重试。攻击次数建议仍是近似值，未实现完整攻击/换弹与 NS 打断调度。
- 不扩展 Boss 血量、阶段或攻击机制，不补齐其他全部特殊效果语义。
- 只保证相同学生数据与规则版本下的分享重放一致；没有冻结历史数据库。旧客户端可能忽略新增等级与时长，导出界面明确提示兼容限制。
- 第一、二步报告及第一步文件指纹清单保持历史原样；保留此前未提交修改，没有暂存或提交。

# 第六步：交付验收整理

本轮仅完成不依赖未实现战斗机制的验收与交付整理。它不表示第五步四批特殊机制或第四步 4.2 的可信普攻循环已经完成。

## 已闭合的交付项

- GitHub Pages 工作流统一到 Node `24.19.0` 与 pnpm `10.34.1`，在推送到 `dev` 及以 `dev` 为目标的 Pull Request 上依次运行测试、Lint、规则登记检查和生产构建；部署步骤仅在 `dev` 推送时执行。
- `package.json` 固定 `pnpm@10.34.1`，README 与 CI 的运行时约定一致。此次本机验收使用 Node `v24.19.0`、pnpm `10.34.1`。
- README 改为事实导向的能力说明：明确学生机制范围、用户事实、自动 NS 的逐技能范围、Boss／普攻的未实现边界、v5 分享和规则支持等级；删除“已模拟 Boss 阶段、完整普攻、全自动 NS”等不准确说法。
- 新增一个稳定的性能验收：以 6 人、5400 帧的三分钟推演测量核心引擎，并以 1,200 条效果审计记录测量时间轴效果视图模型。该测试只设 2 秒的宽松回归上限，不用机器相关的毫秒数作为功能正确性依据。

## 本机结果

| 项目 | 结果 |
| --- | --- |
| 核心 5400 帧推演 | 33.6 ms |
| 1,200 条效果轨道视图模型 | 0.8 ms |
| 全量测试 | 33 个文件、244 项通过；包含性能验收用例 |
| 类型检查、Lint、规则登记、生产构建 | 通过 |
| 规则登记 | 错误 0；仍保留已实现／人工事实／仅状态／部分实现的分级 |

毫秒数据为本机一次测量，用于之后发现明显性能回退；它不是跨设备性能承诺。生产构建仍有单个压缩前 chunk 超过 500 kB 的提示，本轮只记录，不通过跳过合法性检查或降低校验来消除它。

## 浏览器验收状态

计划中的浏览器流程包括：学生搜索筛选、爱用品切换、多目标事件编辑、自动 NS 模式切换、重复推演、召唤目标退场和 v5 分享重放。

本机开发服务可启动，但可用的浏览器自动化运行时两次初始化均失败，错误为 `failed to write kernel assets: 系统找不到指定的路径。 (os error 3)`。因此本轮没有执行或声称通过浏览器点击流程，也没有保留服务进程。该问题不阻塞代码级验收；相关状态、导入导出和引擎路径已由回归测试覆盖。浏览器运行时恢复后，应按上述流程补做视觉与交互验收。

## 明确保留的限制

- 不模拟 Boss 血量、攻击、阶段或真实控制槽。
- 不生成可信普攻、扣弹或换弹记录，攻击次数 NS 仍为待确认建议。
- 自动 NS 仍只限已登记的堇 P/G、明日奈（兔女郎）P；概率、随机、血量阈值和其他外部条件仍由用户录入。
- 未把 `partial` 或 `state_only` 规则表述成完整机制支持。

现有工作区修改保持未提交。
